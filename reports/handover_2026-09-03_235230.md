## Summary

Добавлена команда `$loop`: внешний Python scheduler спит вне модели и через заданный интервал отправляет bounded wake в один явно указанный Codex thread командой `codex queue`. Значение `--max-wakes 8` — безопасный предел по умолчанию, а не технический максимум; например, при `30m` это четыре часа контроля. Лимит настраивается через `--max-wakes`, состояние доступно через `$loop status`, остановка — через `$loop stop`.

Реализация покрывает fail-loud валидацию интервала, thread UUID и queue timeout, включая запрет `NaN`/`inf`; singleton ownership, stale/dead PID handling, атомарное состояние и terminal stop. После прямого probe исправлен пропущенный `--message` в argv `codex queue`. Документация отдельно предупреждает об at-least-once неоднозначности: при локальном timeout удалённый queue уже мог принять wake, поэтому scheduler не делает слепой retry.
