# Handover — Opus 5 takes the Lead and the heavy routing lanes

## Summary

Opus 5 shipped and is judged clearly stronger than Codex Sol and on par with
Fable, so Dmitry moved three routing lanes back to Claude: `lead`, `coding` and
`hard` now resolve to `anthropic:claude-opus-5`. Cheap lanes are untouched
(`trivial`/`recon` on Luna, `medium` on Terra) and `high_blast_radius` stays on
`claude-sonnet-4-6` so the PreToolUse guards keep firing on sensitive writes.

The routing change itself is three lines of data. The work was in making it
actually take effect and not break its neighbours. Two real defects were found
and fixed on the way:

1. **The pin was a silent no-op.** `_with_default_routes()` upgrades an
   already-installed route to the new `DEFAULTS` only on an exact match against
   `_LEGACY_BOOTSTRAP_ROUTES`, which still listed `gpt-5.5` while every live
   install sits on `gpt-5.6-*`. No match means the branch falls through to
   `_normalise_route(current)` and preserves the old route forever. Editing
   `DEFAULTS` alone would have changed nothing on this machine. The map now holds
   a **list** of retired generations per category, and `_with_default_routes()`
   matches against any of them.
2. **`reasoning_effort` leaked across providers.** The migration merges via
   `upgraded.update(default_route)`, which only adds keys — so a category moving
   off Codex kept the old `reasoning_effort: medium`, handing a Codex-only knob
   to an Anthropic route. `_normalise_route()` now strips it for any non-Codex
   provider, which fixes the whole class rather than just the migrated case.

A third issue was a near-miss regression. The installed `model_balancer.py` was
flagged `user-modified` by `install.py` and carried a **runtime-verified**
correction absent from the template: `grok.com` login exposes only `grok-4.5`,
while `grok-build` and `grok-composer-2.5-fast` return "unknown model id"
(verified `grok models` 2026-07-23). A `--force` install would have reverted
three Grok routes to non-existent model ids. The fix was to forward-port that
correction into the template first, then deploy the single file by hand rather
than `--force` (which would also have overwritten local changes in
`pipeline.md`, `phase.py`, `dep_guard.py` and `go.md`).

The cross-provider `/go` invariant needed no structural change: it was always
provider *inequality*, not "Opus reviews Codex". The Worker is now the Anthropic
side and the checkers (Challenge, Verifier, Diff-review) run on Codex, so only
the "today" annotations in `go.md` were stale and were swapped.

## Problems / Solutions

- **Problem:** the routing pin would have silently not applied on this install.
  **Solution:** traced `_with_default_routes()` before editing rather than
  after, found the exact-match requirement, and converted
  `_LEGACY_BOOTSTRAP_ROUTES` to a list of retired generations per category. The
  test now asserts every listed generation migrates, and asserts specifically
  that the `gpt-5.6-*` routes this change moves away from are listed.
- **Problem:** migrating a category off Codex kept `reasoning_effort` on the new
  Anthropic route. **Solution:** stripped it in `_normalise_route()` for any
  non-Codex provider — an output guard at the single choke point, so it also
  covers routes that were never migrated.
- **Problem:** `install.py` reported `0 write, 118 skip, 5 preserve` — the
  deployed balancer was user-modified and `--force` would have clobbered it.
  **Solution:** read the full diff before overwriting, found a runtime-verified
  Grok correction living only in the installed copy, forward-ported it to the
  template, then deployed just that one file (with a backup at
  `/tmp/model_balancer.installed.bak`). Template and deploy now compare
  identical, so a future sync cannot regress it.
- **Problem:** an active `directive` row (`id=46002`, injected into every
  `/start`) asserted `lead/recon/medium/coding/hard → codex-cli:gpt-5.5`, which
  would contradict the code from the next session onward. **Solution:** wrote a
  superseding directive (`id=50822`) recording the new routing *and* the
  explicit no-fallback decision, then retired 46002 after a DB backup.
- **Problem:** `sqlite3 -readonly` on `rolling_memory.db` started returning
  error 14 mid-session where it had worked earlier. **Solution:** read through
  Python with a `file:...?mode=ro` URI instead; no attempt to diagnose the CLI,
  since the read-only contract was satisfied either way.
- **Observation, not fixed:** the routing change produced **no** `transitions[]`
  rows. Migration happens on file load, which bypasses the code path that writes
  the journal, so the routes moved without a recorded "why". Reported honestly
  rather than back-filled.
