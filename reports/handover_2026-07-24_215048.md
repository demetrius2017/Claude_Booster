# Handover — Fable long-consult PTY capture fix

## Summary

This session diagnosed and corrected a Codex integration defect in the Fable
consult path.  The expensive OCR architecture consult was not absent because
Fable was unavailable or because its prompt was intrinsically too large.  Its
wrapper outlived the first shell-tool yield and returned a shell `session_id`.
Codex then waited for the surrounding JavaScript `exec` cell instead of polling
that child PTY with `write_stdin`.  The outer cell therefore resumed without the
child stdout, recording `exit=undefined`; the completed Fable answer was never
collected.

The small `Привет` probe completed in 6.3 seconds, before the first yield, so
it appeared to work and falsely suggested a prompt-size/internal-processing
problem.  The repair makes the lifecycle explicit: a Fable consult is complete
only after the shell session itself has terminated and stdout/stderr plus a real
exit code have been read.

Repository changes are limited to the Codex Fable skill and command templates.
The corresponding installed copies outside this repository were synchronized.
No Fable answer is fabricated: a mistakenly started second real consult was
terminated and its result was not used.

## Problems / Solutions

- **Problem:** a long Fable call yielded a shell session, but the caller used
  `functions.wait` on the outer JavaScript cell.  That operation is not a read
  of the child PTY, so it can return with no exit code and empty pending output.
  **Solution:** both templates now require `write_stdin` polling whenever
  `exec_command` returns `session_id`, and define missing `exit_code` as
  incomplete rather than as a failed/empty consult.
- **Problem:** the 6.3-second greeting call concealed the lifecycle bug because
  it finished before the initial yield.  **Solution:** the contract describes
  the distinction explicitly, preventing future diagnosis from equating a
  completed short call with correct asynchronous capture.
- **Problem:** reissuing a costly architecture consult could create a second,
  untrusted advisory result.  **Solution:** the accidentally started second
  real consult was terminated and deliberately excluded from conclusions.
