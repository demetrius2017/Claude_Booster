# Consilium: Codex `Waiting for agents` history patch

**Date:** 2026-08-05
**Decision:** FOR a narrow, opt-in, TUI-only patch; do not modify runtime waiting
semantics in the first release.

## Task context

Codex CLI can render a repeated pair of history cells while a lead waits for
subagents: `Waiting for agents` followed by `Finished waiting` / no completion.
The intended outcome is to remove this visual noise without losing the lead's
ability to track, contact, navigate to, or receive a final result from every
subagent. The candidate delivery is a locally maintained, version-pinned patch
that can be rebased after upstream updates.

## Verified facts brief

The following facts were verified against the upstream `rust-v0.145.0-alpha.13`
source boundary supplied for this consilium and cross-checked against the current
upstream layout where available. They are not assumptions about later releases.

| Fact | Evidence and consequence |
|---|---|
| Wait history is rendered in the TUI. | `codex-rs/tui/src/multi_agents.rs::tool_call_history_cell` matches `CollabAgentTool::Wait`. Its `InProgress` arm calls `waiting_begin`; its non-`InProgress` arm calls `waiting_end`. |
| The active wait text is presentation-only at this boundary. | `waiting_begin` creates a `PlainHistoryCell` with `Waiting for ...`; it receives receiver ids and metadata only. It does not own agent lifecycle, mailbox, or tool dispatch. |
| Final cells carry meaningful result visibility. | `waiting_end` calls `wait_complete_lines(receiver_thread_ids, agents_states, ...)`, which renders the terminal/result information for addressed agents. |
| The V1 runtime's omitted timeout defaults to 30 seconds. | The core multi-agent common boundary defines the default wait timeout as 30,000 ms; upstream issue #18394 independently describes this hard-coded default. |
| There are distinct TUI navigation/status components. | The TUI tree includes `app/agent_navigation.rs`, `app/agent_picker.rs`, and `app/agent_status_feed.rs`; this supports, but does not prove, separation from history rendering. |

**Unverified / deliberately not claimed:** whether a particular installed binary
has exactly the same call graph as the tag; whether history cells are ever used
as a navigation data source; and whether upstream will accept a configuration
knob. The first implementation must trace callers on the pinned checkout before
editing.

## Positions

External independence is degraded in this consilium. The Codex roles below are
useful independent lenses, but they are same-provider reasoning and are not an
external audit. No unavailable model is attributed an invented opinion.

| Participant | Position | Key insight / KPI |
|---|---|---|
| Rust / TUI architect (Codex) | FOR narrow patch | Hide only `Wait` `InProgress` history cells. It sits at a rendering boundary, so lifecycle and communication semantics remain untouched. KPI: every terminal state remains visible. |
| Lifecycle reviewer (Codex) | FOR with preservation gates | Agent identity, task paths, mailbox delivery, follow-up, approval and `/agent` navigation must remain independent of hidden cells. KPI: spawn → wait → follow-up → completion works with original task path. |

| Grok | Unavailable | No usable response; no opinion recorded. |

## Advocate FOR

The visible churn is generated by a specific TUI conversion of `Wait` tool-call
events into history cells. Returning no cell for the active (`InProgress`) state
is a small, reversible change at the presentation boundary. It removes the most
repetitive card without changing the wait tool's timeout, scheduling, agent
registry, or inter-agent communication. Because final cells remain untouched,
the operator still sees completion, errors and interrupted outcomes.

## Advocate AGAINST

This is an unsupported local fork of an alpha client. An upstream refactor can
move the rendering seam or make history cells feed another UI feature. A patch
can also conceal a real control-plane stall if it is described as a reliability
fix rather than a noise reduction. Finally, lack of a usable external reviewer
means the evidence is weaker than the normal consilium standard.

## Decision

Implement **only** an opt-in TUI policy in the pinned `rust-v0.145.0-alpha.13`
checkout:

```toml
[tui]
multi_agent_wait_history = "hide_in_progress" # default is "all"
```

`all` preserves upstream behaviour exactly. `hide_in_progress` returns `None`
only when `tool == CollabAgentTool::Wait` and
`status == CollabAgentToolCallStatus::InProgress`. All non-in-progress wait
cells continue through `waiting_end` unchanged.

No timeout change belongs in this patch. A 30-second default is a runtime/tool
contract; changing it alters scheduling, responsiveness and potentially agent
control-plane failure modes. This patch is solely presentation control.

There is **no true coalescing in V1** in this release. Coalescing repeated
begin/end pairs into one mutable row requires history-state ownership and a
deduplication key above `tool_call_history_cell`; that is a different, riskier
design.

### Strongest dissent adopted as a constraint

Do not even filter final nonterminal rows in v1. Although it is tempting to
hide `Finished waiting` when no agent completed, determining that safely relies
on complete status semantics and introduces a second policy. Keep every final
wait cell until a later release has dedicated state-model evidence and tests.

## Rejected alternatives

| Alternative | Rejection reason |
|---|---|
| Patch `DEFAULT_WAIT_TIMEOUT_MS` to a longer value | Reduces frequency but changes runtime semantics and can make an actual stall less observable; unrelated blast radius. |
| Suppress all `Wait` history cells | Hides errors, completions and terminal context—the exact signals an operator needs. |
| Filter final no-completion cells in v1 | Requires a correct interpretation of all nonterminal states; no material benefit over hiding active cells and more chance of concealing state. |
| True history coalescing | Requires app/history ownership, mutable prior cells and stable identity/dedup keys; too invasive for the first local patch. |
| Prompt-only workaround | Helps agent behaviour but cannot remove client-generated cards or guarantee an operational status view. |
| Directly modify the package-manager binary | An update overwrites it without an auditable source patch, version guard or deterministic rebuild. |

## Preservation invariants

1. The patch must not modify `wait.rs`, tool dispatch, default timeout,
   `list_agents`, `send_message`, `followup_task`, approvals, agent thread
   state, or task-path persistence.
2. Every terminal wait event remains visible and retains the same
   `wait_complete_lines` output as upstream.
3. Spawn, send-input, resume and close-agent rendering remains byte-for-byte
   equivalent in snapshots where possible.
4. `/agent` navigation and the agent picker operate from the thread/agent store,
   not hidden history cells; this must be demonstrated, not assumed.
5. Unknown config values fail loudly during config validation; omission yields
   upstream-compatible `all`.

## Implementation and release plan

1. Acquire the exact upstream tag in a dedicated local worktree; record commit
   SHA and `codex --version` in a patch manifest.
2. Trace all callers of `tool_call_history_cell` and the data sources for agent
   navigation/status before editing; stop if a hidden cell is a control source.
3. Add a narrowly scoped, validated TUI enum/config setting with default `all`.
4. Gate only the `Wait` + `InProgress` arm in `tool_call_history_cell`.
5. Add unit/snapshot and integration tests below; build the patched binary.
6. Install through a wrapper that first checks the supported version/SHA and
   selects the patched binary only when it matches. Preserve the original binary
   path for rollback.
7. On an upstream update, build a fresh worktree, apply the patch, run all gates
   and only then repoint the wrapper. A conflict means fail closed on stock
   Codex—not a blind text rewrite.

## Acceptance gates

1. Default config snapshot remains unchanged.
2. With `hide_in_progress`, an in-progress `Wait` returns no history cell.
3. With `hide_in_progress`, terminal `Completed`, `Errored` and `Interrupted`
   agent results still render through `waiting_end` with their exact lines.
4. Snapshot coverage proves spawn, send-input, resume and close-agent cells are
   unchanged.
5. End-to-end smoke: spawn an agent, wait beyond 30 seconds, verify the same
   task path via `list_agents`, send it a follow-up, open it through `/agent`,
   and observe its final completion or error in the parent history.
6. Negative config test: an unknown policy value is rejected; omitted policy is
   `all`.
7. Upgrade test: wrapper refuses a mismatched `codex --version`/manifest before
   launching the patched binary.

## Risks and falsifiers

| Risk | Mitigation / falsifier |
|---|---|
| Hidden history cell is secretly a navigation/control source | Trace call graph and smoke `/agent` picker/navigation; any dependence falsifies the narrow-renderer premise and stops the patch. |
| Upstream tag/source differs from installed build | Version/SHA preflight; mismatch runs stock binary and requires a rebase. |
| User mistakes quieter UI for a fixed runtime stall | Release notes state explicitly: visual-noise patch only. Exercise a known stalled wait case separately. |
| Repeated final rows remain noisy | Accepted v1 residual risk; address only after modelling status semantics and adding a history-state design. |
| External review unavailable | Record degraded independence; require stronger local integration evidence and revisit external review when credits/providers recover. |

## Exact rollback

1. Remove or set `[tui].multi_agent_wait_history = "all"`; this restores
   upstream behaviour without rebuilding.
2. If the patched binary itself must be removed, repoint the wrapper to the
   recorded original Codex executable and delete only the dedicated patched
   worktree/build artifact after confirming the wrapper target.
3. On any smoke-test regression, immediately select stock Codex, retain logs
   and patch manifest for diagnosis, and do not attempt an in-place binary edit.

## Residual risk

The patch deliberately leaves `Finished waiting` cards visible. That is a
conscious trade: it preserves evidence of all final wait outcomes and avoids
pretending that a TUI presentation change resolves the underlying wait/polling
behaviour. The downstream agent lifecycle and communication consumers accept
the result only after the acceptance gates prove they read their own thread
state rather than the hidden active history cell.
